# Backend Services, Domain, Tasks — Audit Report

## TL;DR (5 bullets)

- CRITICAL: `RecommendationService` (1234 LOC) duplicates verbatim every method already defined in `RecommendationCrudMixin` (recommendation_crud.py, 541 LOC) and `RecommendationAnalysisMixin` (recommendation_analysis.py, 720 LOC). The class never inherits from the mixins — both mixin modules are entirely dead code, while the production class carries ~2,500 LOC of duplicated logic with two diverging copies of SEC disclosure constants and the N+1-fixed ML pipeline. Any patch to one is silently lost in the other.
- CRITICAL: `realtime_price_service.FinnhubWebSocketClient.connect()` opens `aiohttp.ClientSession` inside an `async with`, then schedules a background `_receive_task` and returns from inside the block. Python exits the `async with`, closing the session, which closes the WebSocket — the receive loop will fire `WSMsgType.CLOSED` immediately on every connect. The real-time price stream is non-functional in production.
- CRITICAL: Almost every "production" code path in `admin_service.py`, `portfolio_rebalancing.py`, parts of `recommendation_service.py`, and `socketio_service._stream_price_updates` returns `random.uniform(...)` / `random.randint(...)` simulated data — yet these values are surfaced to authenticated end-users as portfolio performance, system health, alerts, and live price feeds. There is no `if DEBUG` guard or "stub" warning header. This is a correctness AND compliance hazard (SEC false-data risk for a recommendation/portfolio platform).
- CRITICAL: `backend/tasks/scheduler.py::AsyncScheduler` is wired into `main.py:92-93` lifespan startup but every periodic body (`_periodic_market_data`, `_periodic_portfolio_update`, `_periodic_alert_check`) only logs and sleeps — the actual `celery_app.send_task(...)` calls are commented out. All scheduled background work is silently disabled when the API is the only process running. Combined with `data_pipeline.py` referencing a non-existent `backend.config.celery_config` module, the task subsystem has multiple dead/broken entry points.
- HIGH: `backend/domain/contracts/**` (5 contracts, ~2,690 LOC) is referenced ONLY by `backend/tests/integration/test_domain_contracts.py` — no service or repository implements `MarketDataContract`, `PortfolioContract`, `DataPipelineContract`, `MLContract`, or `InvestmentAnalysisContract`. The DDD layer is an unwired aspirational skeleton, not active architecture.
