# Database, Repositories, Migrations — Audit Report

## TL;DR (REQUIRED — exactly 5 bullets, max)

- CRITICAL: `alembic.ini` line 53 contains a plaintext production database password (`9v1g^OV9XUwzUP6cEgCYgNOE`) committed to the repository; this credential was also flagged as "Exposed" in the Wave 2 ETL report (scope 05) and must be rotated immediately.
- CRITICAL: `AsyncBaseRepository.transaction()` (base.py:667-672) defines `_execute_transaction` as an async generator (`yield session`) but passes it to `execute_with_retry` which calls `await operation()` — awaiting an async generator returns the generator object without executing it, making `transaction()` silently non-functional for all callers.
- HIGH: Migration `adba55bf7b52` creates `idx_watchlists_stock_id` on the `watchlists` table (line 38), but `watchlists` has no `stock_id` column (it belongs to `watchlist_items`); `add_performance_indexes.sql` line 18 makes the same error — both will fail on any database without this phantom column.
- HIGH: All `Exchange`, `Sector`, and `Industry` ORM relationships to `Stock` use `lazy="selectin"` (unified_models.py lines 192, 203-204, 217), meaning any single query on these lookup tables eagerly loads every stock record — a potential multi-thousand-row fanout on every lookup.
- HIGH: Migration `001_add_critical_indexes.py` references columns `confidence_score` (lines 97, 131) and `is_tradeable` (line 177-178) that do not exist in `unified_models.py` — `Recommendation.confidence` and `Stock.is_tradable` are the real names — causing `CREATE INDEX` to fail on a clean database.
